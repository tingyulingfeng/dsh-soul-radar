# 灵魂雷达 · Soul Radar

> 为 DSH 提供判断依据，把阅读反应变成可数的数据。
>
> A simulated reader that turns reading responses into countable data — judgement input for DSH.

**一个模拟读者。** 它把一篇文章读一遍，把「读的时候读者身上发生了什么」拆成数据交给 DSH——
哪里被抬起来了、哪里掉下去了、哪里卡住了、读者会在第几段走神。

DSH 拿这些数据，写成用户看得懂的话。

> 它给大方向，不给判决。工具说「这里读者会掉队」，不等于「这里一定写得差」——
> 有可能作者就是要让读者在这儿卡一下。

---

## 安装

**先看你是哪个 profile。** 桌面版用 `desktop`，网页版用 `web`：

```
dsh plugin --profile desktop add dsh-soul-radar
```

**桌面版也可以直接在应用里点：`设置 → 插件 → 安装`，填 `dsh-soul-radar`。**

**从源码装也行：**

```
git clone https://github.com/tingyulingfeng/dsh-soul-radar.git
dsh plugin --profile desktop add ./dsh-soul-radar
```

装完不需要重启，也不需要另装 Python 或任何运行时——判据逻辑就长在这个包里。

**要求**：DSH ≥ 0.2.2（含 rc 版）。

## 它给你四个工具

| 工具 | 干什么 |
|---|---|
| `lt_score` | 给一篇文章读数，返回读数 + 一份报告 |
| `lt_schema` | 吐标注格式，示例用你传进去的正文真截 |
| `lt_demo` | 看一份存档报告长什么样（样例正文不随包发布） |
| `lt_rules` | 列出全部判据：量什么、什么状态、依据是什么 |

**最小用法：把文章贴进去，剩下交给 DSH。**

```
lt_score({ body: "整篇文章，段不段都行" })
```

**不用自己分段、不用标注、不用选任何东西。** 分段和标注都是 DSH 读完自己做的——分段本身是测量项，所以它算 DSH 的活，不是用户的活。

**不放心的话，让 DSH 先调一次 `lt_schema({ body })`**，它会给出带真实引用的格式说明。

## 也可以不用打字

**侧栏里有一行「灵魂雷达」，点开是一个粘贴框。** 粘文章 → 点复制 → 回对话里粘贴发送。

**就这两步。** 面板不显示分项名、不显示段数字数、不让你选任何东西——它只负责把文章收下来。

（为什么要多一步「复制」：插件拿不到 DSH 的发送接口，猜一个会在点击时报错。**能发就直接发，发不了就老实说「请复制」**，不会给你一个点了没反应的按钮。）

## 你会拿到什么

一份 Markdown 报告，里面分五块：

```
哪里会掉队            段号 + 原因，写「问题结论」和「改良意见」的主要原料
要改但没扣分的        错别字、病句之类：不扣分，但写改良意见时要提
共鸣与系数            读者跟不跟得上，它给所有分项定标
总分 / 额外加分       两个轴，不能相加（见下）
分项表                哪块最弱，决定你骂哪儿
怎么跟他说            你最后要说给用户听的话，按什么结构写
```

### 总分和额外加分是两个轴

```
总分（100 分制）      总体阅读体验。低 = 读者会在某处掉队
额外加分（上限 20）   突出部分有多优秀。低 = 没什么让人记住的地方
```

**不能相加，也不能只看一个。**

```
分项高 + 额外低   稳，但没有亮点
分项低 + 额外高   有亮点，但整体磕磕绊绊
两项都高          难得
两项都低          重写
```

## 它会诚实地告诉你它测不了什么

某一项没标、样本太少、工具看不见——报告里会写「未测」，并且**不进分母**。

```
一篇 88 段的短篇   77.90 / 100.00   八项全测
猫猫庙           74.33 /  88.00   逻辑未标，分母少 12
```

**所以不同文章的分数不能直接横比。要比，先看分母。**

一件工具承认自己看不见，比它假装看得见有用。

---

## 能测什么

**八项全部可测。** 其中两项（语言文字、衔接）直接从文字算，六项需要段落标注——而标注由 DSH 读完自己写，用户不用管。

| 项 | 权重 | 吃什么 |
|---|---|---|
| 氛围铺垫 | 40.75 | 段落标注 |
| 描写叙述 | 15.75 | 承载物标注 |
| 逻辑 | 12 | 逻辑链标注 |
| 语言文字 | 10.5 | **文字本身** |
| 暗线 | 8 | 暗线标注（其中 6 分是标注人估的） |
| 衔接 | 7 | **文字本身** |
| 伏笔 | 4 | 伏笔标注 |
| 笑料与梗 | 2 | 段落标注 |

**没标的项会报「未测」并从分母里去掉，不会算成零分。**

**这也意味着一件事：分数会随标注人浮动。** 同一篇用不同标注能差四五分。所以报告末尾总会写「标注是你自己写的（…）」，别把它当独立测量。

## 描写有两种判法，不能混着看

六类描写对象（景／物／人／事／心理／环境）不是为了数「写了几个角度」，是因为**每一类的「好」标准不一样**：

```
台阶   声音  拟声词 → 直接互动 → 细节+比喻
       心理  直接下结论 → 生理反应 → 潜意识错觉（第三级可选）
       有先后：走到第几级就是第几级

菜单   视觉  颜色 / 光影 / 主观感受
       并列：用两个角度不等于更高级，「第三级不一定更好」

特殊   音乐  时间→空间翻译不了，只能命名曲名 / 大幅旁敲侧击
```

**所以判法不是同一回事**：台阶有先后，菜单只有情况。

工具现在把两种都**读出来**（台阶读到第几级，菜单读到用了哪几个角度），但**都还没进分**——
「描述」的补充依据作者还在写，写完再定这一级怎么加权。扣分侧不受影响，它只问一件事：
情感落没落到具体的物上。

标错会被拒收——给视觉一个 `level` 会直接报错，因为菜单里没有「第三级更好」这回事。

## 三个判据从哪来

1. **作者的理论**——每一条判据背后都有一句原话，`lt_rules` 会把它列出来。
2. **作者一个月里对实测结果的纠正**——「这个数不对」「这两条重复了」。
3. **我的判断**——凡是找不到作者依据的地方，`lt_rules` 的备注里会明写
   「这是我定的，作者还没给」。

**判据表有 49 条：定稿 41、待建 1、已推翻 6。** 已推翻的都留着记录和理由，
因为「为什么不要这条」和「为什么要这条」一样有价值。

### 那些「原话」出自哪里

**出自一个三万字的语料库：[MeowMeow-Kitchen](https://github.com/tingyulingfeng/MeowMeow-Kitchen)。**

《从前有座猫猫庙》的逐句拆解——原创小说，加上人类写作过程的完整记录（CC BY 4.0）。
插件里每一条「补充依据」都能在那里找到出处。

**想看懂这个工具为什么这么判，翻那本书比读代码快。**

## 它不做什么

- **不给文学评价。** 它量的是「读者会不会掉队」，不是「写得好不好」。
- **不替你说话。** 报告是数据包，最终的话由 DSH 写。
- **不改文章。** 只读。
