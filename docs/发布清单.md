## 需要你决定的三件事

### ① GitHub 仓库地址

**package.json 缺 `repository`，README 里也没有链接。**

**开仓库时用这个名字**（按社区惯例，**不要**加 `dsh-plugin-` 前缀——那是索引包的名字）：

```
dsh-soul-radar
```

**给我地址后我补两处：**

```json
"repository": { "type": "git", "url": "git+https://github.com/<你>/dsh-soul-radar.git" }
```

### ② 署名怎么写

**`author` 字段和 LICENSE 里的版权人。** 可以写名字、写 ID、或者留空。

### ③ 两件相关的事

**「猫猫庙」那个语料仓库和这个仓库不能合并**（这是对的建议）**，但可以互链：**

```
插件仓库 README 里   →「这套判据的理论来源：<猫猫庙仓库链接>」
猫猫庙仓库 README 顶部 →「本理论已落地为插件 dsh-soul-radar」
```

**但注意：`lib/samples/` 里内置过那篇样文的全文。** 如果这篇要单独发表，得确认能不能放进开源包。**不行的话我把它换成一篇明确 CC0 的短文。**

## 发布步骤

### 第 1 步：建 GitHub 仓库

**把我给你的 `plugin-release/` 推上去。** 仓库里已经是一个干净的 git repo（`git log` 有 10 次提交）。

### 第 2 步：发 npm

```bash
npm publish
```

**需要 npm 账号。** 包名 `dsh-soul-radar` 如果被占，换成 `@你的scope/dsh-soul-radar`。

**发布前建议先试装：**

```bash
npm pack                      # 打一个 tarball，检查内容
npm install -g ./dsh-soul-radar-0.1.0.tgz   # 或用 dsh plugin add
```

### 第 3 步：让人搜得到

**DSH 的插件发现走的是 `dsh-plugin-catalog`**（npm 包，10581 条），它的上游是：

```
github.com/awesome-dsh-plugin/awesome-dsh-plugin
```

**去那个仓库提 PR/issue，按它的条目格式加一行。进了它，用户在 DSH 的 `Plugins → Discover` 里就能搜到。**

**顺带：npm keywords 里已经有 `dsh-plugin` 和 `deepseek-harness`，这两个是索引用的标签。**

### 第 4 步（可选）：装 dshmarket 看效果

**你机器上已经装了 `dshmarket`。** 发布后打开 `Settings → Plugins → Plugin Market` 就能搜自己的插件，确认收录成功。

## 已知的、公开时要写明的局限

**这些不藏着，README 里已经写了大半：**

```
· 六项判据吃标注，分数会随标注人浮动四五分
· 纯文本只能测两项（语言文字、衔接）
· 短篇（<10 段）多数项按小样本算，分数不稳
· 工具量的是「读者会不会掉队」，不是「写得好不好」
```

**一条工具承认自己测不准，比它假装测得很准有用。** 这是这份插件最该守住的姿态。
