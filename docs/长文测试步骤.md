# 长文测试步骤

> 2026-11-14 第一次用长文测过一轮（1091 段 / 2.3 万字），暴露了三处「按绝对次数算」的毛病，已在 0.4.1 修掉。
> 这份是下次再测长文时照着走的单子——以及**跨版本比分数之前必须先看的那张表**。

## 0. 先确认测的是新代码

插件是装到源码目录上的（junction），但**工具是进程启动时读进内存的**。不重启就是旧代码。

```
① 关掉 DSH 窗口，确认托盘 / 任务管理器里没有 DeepSeek Harness.exe
② 重新打开
③ 新会话里输入：调用 lt_schema，正文用：雨下了一夜。
```

看 `carriers` 那节有没有这三样：`chan 可选` / `台阶 / 菜单 / 特殊` / `不许给 level`。
**没有就是没重启干净**，别往下测——你测的东西和你看的代码不是同一份。

## 1. 开场白（可直接复制）

最短、最接近真实用户：

```
用灵魂雷达分析这篇，一段一行：

（正文粘这里）
```

想顺带测判法读数，加一句：

```
用灵魂雷达分析这篇，一段一行。承载物那部分，能判通道的标上 chan（声音/视觉/心理/音乐），台阶类给 level，菜单类给 angles：

（正文粘这里）
```

## 2. 长文怎么传

**正文整段传进 `body`，代码里没有长度上限**——1091 段也能一次传过去。

如果 DSH 那边把参数截断，会报 JSON 格式错（「不是合法 JSON」或「正文里找不到」），那才是真限制，不是插件的。

**别让它绕过 `lt_score` 直接调 `lib/`**：那样也能出报告，但跳过了标注校验——段数对不上、引用定位不到，都不会报，你拿到的数看着正常、其实没验过。

## 3. 验收清单

| 看哪里 | 应该是 |
|---|---|
| 总分行 | `NN.N / MM.M`，**MM 不一定是 100**——有未测项分母就小，别拿它和别的文章横比 |
| 分项表 | 8 行都在；缺的进「未测项」，**不进分母、也不算零分** |
| 「哪里会掉队」 | 同类问题合并成「两条例样 + 同类还有 N 处」；**不同类的问题都要露头** |
| 「描写判法」 | 有这一节 = 判法读数在；如果标了 chan，最后应该是「只报读数，不进分」 |
| 「要改但没扣分的」 | 台阶没走满的会有「段 N 的X停在「…」——往下还有 …」 |
| 额外加分 | 结尾标「直接终结」时，形式 0/4 下面会有一句「这 0 分是有意的」 |
| 报告最末 | 「标注是你自己写的（…）」——说明这是它的阅读，不是测量 |

**故意挑一个错试试**：让它给某处视觉描写标 `level: 3`，应该报

```
carriers[k].level：视觉是「菜单」判法，没有级数这回事——颜色 / 光影 / 主观感受 是并列的…
```

## 4. 长文最容易出的三件事

1. **段数对不上**：报「给了 N 段，正文有 M 段」就回它「补齐，一段都不能少」。宁可报错，不许错位。
2. **标注一次写不完**：让它先只给 `paras` 跑一版（起伏、笑料、衔接、段长能算），第二次再补 `carriers` / `chains` / `theme` / `ending`。两版分母不同，**别横比总分**。
3. **它自己按语义分段**：分段不同分数会变，那是设计（分段本身是测量项）。如果原稿是一整块，它会先警告「这篇是一整段」再照算——**那句警告在，就说明它没偷偷替你分段**。

## 5. 比分数之前先看这里

判据在 2026-11-13 和 11-14 改过三次，**同一个数在不同版本里不是一个意思**：

| 版本 | 变了什么 | 88 段样例总分 |
|---|---|---|
| 0.3.1 及以前 | — | 77.45 |
| 0.4.0 | 判法读数（只读，不进分） | 77.45 |
| 0.4.1 | 连贯按密度；暗线按交集点归一；提示同类合并 | **77.90** |

**长文受影响比短文大得多**（同一篇 1091 段 / 2.3 万字，同一份标注）：

| | 旧尺子 | 0.4.1 |
|---|---|---|
| 氛围铺垫 | 31.23 / 40.75 | ≈35.7 |
| └ 连贯 1-3 | 0 / 8.1（28 处跳变直接清零） | 71.8% |
| 暗线 | 2.55 / 8（位置分 1.4%） | ≈4.1（位置分 75%） |
| **总分** | **79.08** | **≈85.2** |

**所以跨版本比同一篇时**：0.4.1 之前的长文都被「按次数」压低了，短文不受影响。新旧版本之间的差，不是这篇写变好了。

## 6. 出了问题贴回来什么

1. **完整报告原文**（至少：总分行、分项表、掉队那节、任何报错原文）
2. **哪一步别扭**（「它没分段」「它没标 chan」「这个数明显不对」）
3. **正文大致段数 / 字数**

## 附：只有段落标注时能重算什么

长文重算时，如果手里只有 `paras`（四字编码），能算：氛围、笑料（要正文里的字数）；**算不了**：衔接、语言、逻辑、暗线位置（都要正文或其它标注）。

所以**正文和标注一起存下来**，下次才能整篇重算——别只存 paras。
